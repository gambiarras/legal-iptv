公開されているIPTVおよびライブストリーミングソースをまとめて、静的なM3Uプレイリストにします。

このプロジェクトは、以下のような複数のソースからチャンネルを集約しています：

- IPTV-ORG  
- `extra_channels.json` から手動で選定されたチャンネル  
- `live-stream-catalog` によって生成されたチャンネル

出力されるのは静的な `playlist.m3u` ファイルで、有料ホスティングを必要とせずに GitHub を通じて公開することができます。

## 動作の仕組み

このプロジェクトは、さまざまなソースからチャンネルを取得し、統合します：

### 1. IPTV-ORG
IPTV-ORGの公開データセットから、チャンネルのメタデータ、ストリームURL、およびロゴを読み込みます。

### 2. 追加チャンネル
`extra_channels.json` から手動で選定されたチャンネルを読み込みます。

### 3. live-stream-catalog
`live-stream-catalog`リポジトリから動的に解決されたチャンネルを読み込みます。

このソースには、次のようなメタデータが含まれる場合があります：

- `stream_url`
- `status`
- `resolved_at`
- `expires_at`
- `ttl_seconds`

集約パイプラインはチャンネルをフィルタリングして選択し、最終的なM3Uプレイリストを生成します。

## ローカルでの利用方法

同一マシン上で両方のリポジトリを実行する場合は、ローカルに保存された `live-stream-catalog` の出力を使用してください：

```bash
python3.11 -m legal_iptv \
  --live-catalog-file../live-stream-catalog/channels.json \
  --output playlist.m3u \
  --meta-output playlist.meta.json
```

`--live-catalog-file`オプションが指定された場合、そのファイルは必ず存在していなければなりません。これにより、ローカルで実行される際に誤って遠隔のカタログに自動的に切り替わることを防ぎます。

`live-stream-catalog`に記載されたチャンネルは、手動で選定された追加チャンネルやIPTV-ORGのチャンネルよりも優先して選ばれます。重複する候補が同じURLを指し、名称も同じまたは非常に似ている場合は、最も適切な候補のみが保持されます。URLが異なる場合は、両方とも保持され、重複するチャンネルIDは一意になります。

プレイリストを生成する前に、ストリームのURLを検証するオプションもあります：

```bash
python3.11 -m legal_iptv \
  --live-catalog-file../live-stream-catalog/channels.json \
  --validate-streams \
  --validation-max-workers 32 \
  --validation-timeout 6
```

デフォルトでは、各ストリームURLに対してネットワーク接続状況のチェックを行うため、検証機能は無効になっています。有効にすると、各URLの最新のステータスが `stream-status.json` に記録されます。

スケジュール済みの環境では、このリポジトリの外部で定期的に、例えば4時間ごとに検証を実行してください。通常のプレイリスト生成時には `stream-status.json` を読み込み、最近オフラインとしてマークされたURLはスキップします。

```bash
python3.11 -m legal_iptv \
  --live-catalog-file../live-stream-catalog/channels.json \
  --stream-status-file stream-status.json \
  --stream-status-max-age 14400
```

`--stream-status-max-age`より新しいオフラインステータスのみが適用されるため、古くなったエラー情報がチャンネルの利用を永続的に妨げることはありません。
